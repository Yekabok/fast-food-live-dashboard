# Core User Journeys

## Journey 1: View nearby store performance
### Goal
Find out which nearby fast food store is performing best right now.

### Steps
1. User opens the website on mobile or desktop.
2. User allows location access or enters an area manually.
3. System displays nearby stores in a dashboard list.
4. User scans gauges for service, speed, freshness, and order accuracy.
5. User checks confidence and last updated time.
6. User decides which store to visit.

### Success outcome
The user can make a quick, informed decision without reading detailed reviews.

## Journey 2: Submit a recent experience rating
### Goal
Contribute a recent store experience so the dashboard remains current.

### Steps
1. User signs in with Google or Apple.
2. User selects the store they visited.
3. User rates service, speed, freshness, and order accuracy.
4. User submits the rating.
5. System confirms the contribution and updates the user profile.

### Success outcome
The user can contribute in under a minute with minimal friction.

## Journey 3: Judge signal reliability
### Goal
Understand whether a visible store score is based on enough recent feedback to trust.

### Steps
1. User views store gauges on the dashboard.
2. User checks the confidence indicator.
3. User checks the last updated time and current time window.
4. User decides whether the signal is strong enough to rely on.

### Success outcome
The user can distinguish between strong live signals and low-data situations.

## Journey 4: Review historical trend data
### Goal
Understand how a store or group of stores has performed over time.

### Steps
1. User navigates to a trends or analytics view.
2. User selects a time period such as last week or last month.
3. User reviews trend charts or summary comparisons.
4. User identifies patterns or changes in performance.

### Success outcome
The user can see how current performance compares to historical behaviour.
