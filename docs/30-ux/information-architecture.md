# Information Architecture

## Top-level navigation
- Dashboard
- Sign In
- Profile
- Trends
- About / Methodology

## 1. Dashboard
### Purpose
Primary public view for comparing nearby fast food stores based on recent customer-rated performance.

### Key content
- area selector
- store list
- metric gauges
- confidence indicators
- last updated timestamps
- time-window selector
- sorting controls

## 2. Sign In
### Purpose
Enable returning users to authenticate using supported identity providers.

### Key content
- Google sign-in
- Apple sign-in
- privacy and terms links

## 3. Profile
### Purpose
Allow authenticated users to view their account identity, contribution history, and badges.

### Key content
- display name
- contribution count
- badges
- recent contributions

## 4. Trends
### Purpose
Provide historical performance views separate from the live dashboard.

### Key content
- date-range selector
- store comparison views
- trend charts by metric
- summary insights

## 5. About / Methodology
### Purpose
Explain what the product does and how to interpret the data.

### Key content
- what the gauges mean
- how confidence works
- what time windows mean
- how ratings are collected
- privacy and trust information

## Structural principles
- The dashboard is the default landing experience.
- Historical insights should be clearly separated from live signals.
- Trust and methodology information should be easily reachable from the dashboard.
- Authenticated contribution flows should require minimal navigation depth.
